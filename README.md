# Ferrum Chess

Ferrum Chess is an experimental, offline native chess application in Rust. It uses `iced` for the interface, MIT-licensed `cozy-chess` for standard chess rules and SAN, and communicates with a separate Stockfish process over UCI. No online API or server is used by the application.

## Implemented

- Play against Stockfish with selectable search depth, or choose analysis mode to play both sides and see an evaluation and best-move indicator. Engine calculations run on a worker thread.
- Click a piece and its destination, or drag from one square to another. Legal destinations and the last move are highlighted. Select the promotion piece **before** moving a pawn to its last rank.
- New game, choose a side (starts a new game), restart, and undo. Undo normally takes back both a human move and the engine response in play mode, or one ply in analysis mode.
- Load/save UTF-8 PGN using a file dialog. The reader preserves `Event`, `Site`, `White`, `Black`, and `Result`, reads SAN and a standard FEN starting position, and rejects illegal moves. It skips comments, NAGs, and nested variations; it does not preserve them. Unsupported tags are discarded. One main-line game per file is supported.
- The direct UCI adapter uses `uci`/`isready`, checks the engine's move against the board, limits each search to 15 seconds and reports timeouts, invalid output, or startup errors in the UI. Changing position or settings cancels the old search; the worker kills and reaps the child process.

## Build and run

Install a current stable Rust toolchain with rustfmt and clippy, then:

```sh
cargo build --release
cargo run --release
```

For Linux local builds, iced/rfd may require native windowing libraries, for example `libxkbcommon-dev libwayland-dev libasound2-dev libudev-dev` on Debian/Ubuntu. Install Stockfish separately for local builds: the application looks for `stockfish.exe` (or `stockfish` on Unix) beside its own executable, then on `PATH`. Alternatively set `FERRUM_STOCKFISH` to the executable path. For example, place `stockfish.exe` next to `target/release/ferrum-chess.exe`.

Before a PR run:

```sh
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

Set `FERRUM_STOCKFISH` when running tests to enable the real-engine integration test. Unit tests also compile and run a tiny fake UCI executable to test protocol handling and cancellation.

## Windows CI and releases

`.github/workflows/release.yml` is a **hand-maintained** workflow using `cargo-dist` for the Windows application build and WiX 4 for the MSI, with extra steps to include Stockfish. It is not a workflow generated by `dist init`: cargo-dist could not be installed in the restricted development environment. Regeneration and reconciliation with cargo-dist's generated workflow remain outstanding. `dist-workspace.toml` sets `allow-dirty = ["ci"]` for the hand-maintained workflow.

On pull requests and `v*` tag pushes the Windows job is intended to run formatting, Clippy, tests (including real Stockfish), a license audit, cargo-dist and MSI builds, and installation/engine/uninstallation smoke checks. PR packages are uploaded as workflow artifacts. A tag push publishes a release **only after** these steps pass. The tag must exactly match the `X.Y.Z` version in `Cargo.toml`, e.g. `v0.1.0`. Release artifacts are an MSI, standalone app and Stockfish EXEs, a portable ZIP containing both and license notices, the resolved `Cargo.lock`, and Stockfish source/distribution archives. Portable users must put both executables in the same directory (or use PATH). The MSI is unsigned and may trigger SmartScreen.

No `Cargo.lock` is checked in yet: create and commit one on a machine with registry access before relying on reproducible releases. A lockfile produced by the workflow is attached to its artifacts, but does not make earlier builds reproducible.

## Ограничения и непроверенное

- **CI has not been run for these changes.** No successful build, Clippy run, unit/integration test run, cargo-dist build, MSI build, or GitHub release is claimed. The sandbox has no crates.io access or suitable local build environment; local compilation was not attempted. Local formatting was run, but it is not a substitute for Windows CI.
- Windows GUI launch and rendering, drag-and-drop, the human-move/Stockfish-reply flow, Stockfish launched from an installed MSI, and MSI installation **and removal** remain unverified. The scripted smoke checks are not a substitute for interactive Windows testing.
- Only standard chess is supported. `cozy-chess` detects checkmate, stalemate and the 50-move threshold, but this application does not track threefold repetition or insufficient-material draws. The engine receives the current FEN, not the history needed for repetition evaluation.
- The PGN reader deliberately implements a subset, not the full PGN specification: UTF-8, one game, ordinary one-line tag pairs and canonical SAN. Other tags, comments, annotations and variations are not round-tripped. An imported declared result is retained until a move, undo, or restart.
- The hint is a line and endpoint rather than an arrowhead. The board is fixed at 512 × 512; a dragged piece is not animated beneath the pointer. There are no clocks or online games.
- The UCI worker has deadlines and cancellation, but arbitrary external processes and OS I/O can still fail; only a trusted Stockfish binary should be used.
